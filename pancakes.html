Pancakes Coffee — designing from an audit finding, not a mood board

A website, customer loyalty app, and internal ops dashboard for a 5-branch Cairo cafe brand — built from a real competitive audit, not a visual brief.

Role
UX audit, UI design, frontend build
Tools
Figma, React, HTML/CSS
Surfaces
Website · Loyalty app · Admin dashboard
Status
Concept project, not a live client build
01 — The Finding
The brief, found not assigned

A message sent to Pancakes with real purchase intent went unanswered. The same test on a direct competitor got an automated reply in seconds. That single, measurable gap — not a rebrand wish — became the brief.

Rather than starting from a visual mood board, I started from a real, testable gap in customer response time and worked backward to what digital surfaces could close it.

02 — Deliberate Non-Choices

What I deliberately didn't copy

The competitor that prompted this audit leaned into a quiet "study cafe" positioning. I chose not to follow it:

  • Their "study cafe" positioning — it conflicts with Pancakes' social identity
  • Any shift toward a quieter, workspace feel
  • Their product lineup or tone, wholesale

The goal wasn't to imitate a competitor's system — it was to close a specific, measured gap while keeping what makes Pancakes itself.

03 — What I Built

Three connected surfaces

A website that communicates the social/dessert identity, a low-friction loyalty app (WhatsApp/QR — no download required), and an owner-facing dashboard to see whether any of it actually worked.

Website homepage — redesigned around the brand's social/dessert identity rather than the competitor's study-cafe tone.
Loyalty app — points balance, redeemable rewards, and recent activity. Built as working React, with real interaction states for redeeming a reward.
Owner-facing ops dashboard — revenue, order channels, review snapshot, and loyalty activity, so the impact of the redesign is actually visible.

05 — Designed vs. Built
Designed
  • Full Figma design system: color and type tokens, spacing scale
  • Website, loyalty, and dashboard screens, wireframe through hi-fi
Built
  • Working React components for the loyalty screen and ops dashboard — real state, not a flat comp
  • Config-driven structure (a single CAFE_CONFIG block) so the same system could theoretically serve another cafe client
06 — What I Caught on Review

Accessibility audit, not eyeballing

Before treating any screen as final, I ran actual WCAG contrast math on the shipped color tokens — and found two real failures before they could reach a client.

3.61:1
Label text vs. cream — fails AA
2.29:1
Reward icon contrast — fails AA
15.21:1
Headline contrast — passes AAA
07 — What I Learned

An audit finding is a stronger brief than a mood board

This project shaped how I now start every design engagement: find a real, testable gap before touching color or type. It also pushed me to treat accessibility as something I verify with numbers, not something I eyeball at the end — a habit I've carried into every project since.
